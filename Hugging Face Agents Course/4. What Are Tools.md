# What Are Tools?

[Course page](https://huggingface.co/learn/agents-course/unit1/tools)

A **tool** is a callable function that gives an agent a capability beyond the model's own text generation. Each tool should have a clear purpose and complement what the model can do.

- **Web search:** find current information.
- **Retrieval:** access information from external documents or databases.
- **Calculator:** perform arithmetic reliably.
- **Image generation:** create images from a description.
- **API interface:** interact with services such as GitHub or Spotify.

Training gives a model knowledge of past data, not a live connection to the world. A request for today's weather needs current information supplied through context or a tool; the model's training alone cannot establish it.

## How a tool call works

**The model requests an action; the agent's software executes it.** Providing a tool description lets the model choose that capability, but does not make the model execute the function itself.

For a weather request:

1. The model receives descriptions of the available tools and their inputs.
2. It generates a request such as `weather_tool("Paris")`.
3. The agent's software identifies the request and calls the actual weather function.
4. It adds the result to the conversation and sends the updated context to the model.
5. The model uses that result to answer the user or choose another action.

The invocation can be represented as code, JSON, or another precise format the agent understands. The interface may hide the intermediate calls from the user.

## What the model needs to know

A tool has two sides: **a description for the model** and **an implementation for the software to execute**. The model needs:

- A meaningful name and an accurate description of what the tool does.
- Argument names, meanings, and types.
- The expected output, optionally with its type.

For example:

```python
def calculator(a: int, b: int) -> int:
    """Multiply two integers."""
    return a * b
```

Its description can be serialized as:

```text
Tool Name: calculator
Description: Multiply two integers.
Arguments: a: int, b: int
Outputs: int
```

The course inserts these descriptions into a tools section of the system message. Use a consistent, precise format across tools so the model knows what it can request and which arguments to supply. The implementation's source code is not required for the model to choose the tool.

## Generating descriptions from Python functions

Manually maintaining tool descriptions can lead to omissions and inconsistencies. Python functions already expose useful metadata through names, docstrings, and type hints.

The course demonstrates an illustrative `Tool` wrapper that stores `name`, `description`, `func`, `arguments`, and `outputs`:

- `to_string()` formats the metadata into a description for the prompt.
- `__call__(*args, **kwargs)` forwards execution to the wrapped function.

A `tool` decorator can build that wrapper automatically:

1. Use `inspect.signature(func)` to retrieve parameter names, annotations, and the return annotation.
2. Read `func.__name__` for the name and `func.__doc__` for the description.
3. Return a `Tool` instance containing that metadata and the original callable.

With the course's decorator and wrapper defined, usage becomes:

```python
@tool
def calculator(a: int, b: int) -> int:
    """Multiply two integers."""
    return a * b

print(calculator.to_string())  # Description for the model
result = calculator(6, 7)     # Executes the function: 42
```

This is a simplified teaching implementation, rather than a specific library API. The decorator registers the function's metadata and callable; the surrounding agent still needs to select, execute, and return tool results.

## Model Context Protocol (MCP)

**MCP** standardizes how applications connect to tools and other context sources. Compatible agent frameworks can reuse MCP integrations instead of implementing a separate tool interface for each framework.

It standardizes access to capabilities; the model still requests actions through the agent application.
