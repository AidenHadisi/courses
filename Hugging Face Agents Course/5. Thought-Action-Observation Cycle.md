# Thought–Action–Observation Cycle

[Course page](https://huggingface.co/learn/agents-course/unit1/agent-steps-and-structure)

An agent works through a repeating cycle: **decide what to do → act → observe the result → decide again**. It uses feedback from its environment to move toward the user's objective.

## The three steps

- **Thought:** the model uses the task and available context to decide the next step. It may need more information, a tool call, or a final response.
- **Action:** the agent carries out the chosen action, such as executing a tool with the model's selected arguments.
- **Observation:** the tool's result becomes additional context. On the next pass, the model uses this feedback to assess what happened and choose how to proceed.

The observation is the returned information; interpreting it informs the next thought. It can contain useful data, an error, or an incomplete result.

## Repetition and stopping

Think of the workflow as a `while` loop that continues while more work is needed. A plan can change after each observation instead of committing to every step in advance.

If a tool fails or returns insufficient information, the agent can adjust its approach and act again. Once it has enough information to fulfill the request, it produces a **final answer**, ending the cycle.

Fresh feedback helps ground the response in external information, but the agent still needs to interpret that feedback correctly.

## Example: current weather

The user asks for the current weather in New York.

1. **Decide:** current conditions require a weather lookup.
2. **Act:** request the weather tool with a location argument:

   ```json
   {
     "action": "get_weather",
     "action_input": {
       "location": "New York"
     }
   }
   ```

3. **Observe:** the application executes the tool and adds its result to the context. An example result is partly cloudy, 15°C, with 60% humidity.
4. **Decide again:** the returned data is sufficient to answer the question.
5. **Finish:** give the user the weather report.

An error at step 3 would call for another decision rather than presenting invented conditions as the tool's result.

## Instructions and execution

The course's example system prompt defines:

- The assistant's behavior and objective.
- Available tools and their inputs and outputs.
- The repeating thought–action–observation workflow.
- How to format a tool request or signal a final answer.

It uses markers such as `Thought:`, `Action:`, and `Final Answer:` as an illustrative format. The application must still execute requested tools, supply observations, and manage continuation; prompt instructions describe the workflow.

This interaction between reasoning and actions is the core idea behind **ReAct**, explored in the next lesson.
