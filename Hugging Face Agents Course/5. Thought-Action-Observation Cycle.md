# Thought–Action–Observation Cycle

Course pages: [Cycle overview](https://huggingface.co/learn/agents-course/unit1/agent-steps-and-structure), [Thoughts and ReAct](https://huggingface.co/learn/agents-course/unit1/thoughts)

An agent works through a repeating cycle: **decide what to do → act → observe the result → decide again**. It uses feedback from its environment to move toward the user's objective.

## The three steps

- **Thought:** the model uses the task and available context to decide the next step. It may need more information, a tool call, or a final response.
- **Action:** the agent carries out the chosen action, such as executing a tool with the model's selected arguments.
- **Observation:** the tool's result becomes additional context. On the next pass, the model uses this feedback to assess what happened and choose how to proceed.

The observation is the returned information; interpreting it informs the next thought. It can contain useful data, an error, or an incomplete result.

### What thoughts contribute

Thoughts use the available context to analyze the task, form a plan, and adapt it. Common purposes include:

- **Planning:** divide the task into smaller steps.
- **Analysis:** interpret evidence, such as an error message.
- **Decision making:** choose an option that fits constraints.
- **Problem solving:** choose an approach, such as profiling before optimization.
- **Memory integration:** use earlier context, such as the user's preferred language.
- **Self-reflection:** change strategy after an unsuccessful attempt.
- **Goal setting:** establish what successful completion means.
- **Prioritization:** decide which work matters most or comes first.

Using earlier conversation context does not by itself imply a separate memory system. An explicit textual thought step is also optional for models trained to produce tool calls directly.

## Repetition and stopping

Think of the workflow as a `while` loop that continues while more work is needed. A plan can change after each observation instead of committing to every step in advance.

If a tool fails or returns insufficient information, the agent can adjust its approach and act again. Once it has enough information to fulfill the request, it produces a **final answer**, ending the cycle.

Fresh feedback helps ground the response in external information, but the agent still needs to interpret that feedback correctly.

## Example: current weather

The user asks for the current weather in New York.

1. **Decide:** current conditions require a weather lookup.
2. **Act:** request the weather tool with a location argument:

   ```json
   {
     "action": "get_weather",
     "action_input": {
       "location": "New York"
     }
   }
   ```

3. **Observe:** the application executes the tool and adds its result to the context. An example result is partly cloudy, 15°C, with 60% humidity.
4. **Decide again:** the returned data is sufficient to answer the question.
5. **Finish:** give the user the weather report.

An error at step 3 would call for another decision rather than presenting invented conditions as the tool's result.

- The assistant's behavior and objective.
- Available tools and their inputs and outputs.
- The repeating thought–action–observation workflow.
- How to format a tool request or signal a final answer.

It uses markers such as `Thought:`, `Action:`, and `Final Answer:` as an illustrative format. The application must still execute requested tools, supply observations, and manage continuation; prompt instructions describe the workflow.

## Chain-of-Thought and ReAct

**Chain-of-Thought (CoT)** prompting encourages intermediate reasoning before the final answer. It can use worked examples or a cue such as “Let's think step by step.”

For example, calculating 15% of 200 can be broken into 10% (20) plus 5% (10), giving 30. The reasoning uses information already in the problem; no external tool is needed.

**ReAct — Reasoning + Acting** interleaves reasoning with actions and observations. A tool result supplies new information that can change the next decision. The weather example above follows this pattern.

- **CoT alone:** useful for reasoning over supplied information, such as a logic or arithmetic problem. Reasoning alone cannot supply missing live data.
- **ReAct:** useful when solving the task requires external information or actions, especially when later steps depend on earlier tool results.

Both involve reasoning; ReAct adds interaction with the environment. The lesson's comparison image illustrates CoT prompting, without tool calls or observations.

## Prompting versus training

CoT and ReAct can be introduced through prompting: instructions or examples guide how the model approaches the task. Other models receive additional training specifically to develop reasoning behavior.

These are different ways to shape behavior and can be combined. A reasoning-trained model can still use tools in a ReAct-style workflow.

How reasoning is represented or exposed depends on the model and interface. Tokens such as `<think>` and `</think>` are model-specific conventions, not a requirement shared by all reasoning models.
