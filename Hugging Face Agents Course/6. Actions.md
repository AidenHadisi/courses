# Actions

[Course page](https://huggingface.co/learn/agents-course/unit1/actions)

An **action** is a concrete operation an agent takes to interact with its environment. The model describes the operation and its arguments; the surrounding software executes it.

Actions can gather information, call APIs, perform calculations, operate interfaces or physical devices, and communicate with users or other agents. A customer-service agent might retrieve an account, find a support article, or transfer an issue to a person.

## Representing actions

- **JSON agent:** describes the tool and its arguments in a structured JSON object.
- **Code agent:** generates a code block for an external execution environment to run.
- **Function-calling agent:** uses a model trained to emit structured tool-call messages. The course groups this with JSON agents because calls identify a function and its arguments; the exact message format depends on the interface.

These describe how an action is expressed, rather than different goals the agent can pursue.

## Stop and parse: handing over control

The model must finish the action request and **yield control before the tool result is available**. The application then:

1. Recognizes the end of the request using the expected action boundary.
2. Parses the structured output to identify the tool and arguments, or the code to execute.
3. Executes the operation.
4. Returns its output as an observation for the next model step.

For example:

```json
{
  "action": "get_weather",
  "action_input": {"location": "New York"}
}
```

The parser extracts `get_weather` and the `location` argument. The model pauses while the application performs the lookup, rather than continuing to generate a supposed result itself.

A predetermined format makes requests easier to parse and reduces ambiguity. Function-calling interfaces provide structured boundaries for the same handoff.

## Code agents and composition

Code can express loops, conditions, reusable functions, and data transformations within one action. It can also work with existing libraries and APIs, with programming errors available as feedback for correction.

For example, assuming `get_weather` is an available tool, one generated code action could be:

```python
weather_by_city = {}
for city in ["New York", "Paris"]:
    weather_by_city[city] = get_weather(city)

print(weather_by_city)
```

The execution environment runs the code and returns the captured output. **Printing produces execution output; it is not what stops the model's generation.** The code block must already have been completed and handed to the executor.

The lesson's illustration compares smartphone purchase costs across countries. A JSON-style workflow makes successive requests to look up prices and rates, convert currencies, and include taxes and shipping. A code action can compose those tools in a loop and use Python's `min` to select the cheapest result.

This can reduce model-to-executor round trips by grouping operations in one program. The underlying tool and API calls still need to run.

## Executing generated code

Generated code can perform harmful operations, including operations induced by prompt injection. Run it with restricted permissions and an appropriately isolated execution environment. Agent frameworks can provide safeguards, but their protection depends on the executor and its configuration.
