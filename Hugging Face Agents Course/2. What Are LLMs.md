# What Are LLMs?

[Course page](https://huggingface.co/learn/agents-course/unit1/what-are-llms)

A **large language model (LLM)** learns language patterns from large text datasets. In an agent, it interprets instructions, uses the conversation context, plans, and chooses tools. Generative LLMs do this by repeatedly predicting the next token from the preceding tokens.

## Transformer architectures

Most modern LLMs use the **Transformer** architecture, built around attention. Its three main forms serve different purposes:

- **Encoder-only:** turns input into contextual representations that capture information about the text. Used for classification, semantic search, and named entity recognition. Example: BERT.
- **Decoder-only:** generates a continuation one token at a time. Used for chat, text generation, and code generation. Example: Llama.
- **Encoder–decoder (sequence-to-sequence):** an encoder represents the input, and a decoder uses that representation to generate an output sequence. Used for translation, summarization, and paraphrasing. Examples: T5 and BART.

The generative LLMs commonly used as agent brains are typically decoder-based models with billions of learned parameters. Parameter count alone does not define an architecture.

### How can a decoder-only model read input?

**Representing input does not require a separate Transformer encoder.** Both architectures tokenize the input and turn tokens into vectors. A decoder-only model processes those vectors through its own Transformer layers before predicting a continuation.

- **Encoder–decoder:** a separate encoder processes the input with bidirectional attention. The decoder generates output using earlier output tokens and attention to the encoder's representations (cross-attention).
- **Decoder-only:** one stack processes the prompt and its generated continuation using causal self-attention. Each position can use itself and earlier positions; when predicting an answer token, the entire preceding prompt is available.

For example, a decoder-only model can continue `Translate to French: Hello. Answer:` with `Bonjour`. Translation and summarization are possible with either architecture; the task does not determine the architecture.

## Tokens and special tokens

A **token** is a unit of input or output. It can represent a whole word, part of a word, punctuation, or other text. Tokenization often uses reusable subword units, allowing a limited vocabulary to represent many words.

For example, a tokenizer might represent “interesting” as `interest` + `ing`, and “interested” as `interest` + `ed`. The actual split depends on the tokenizer.

**Special tokens** mark structure, such as the start or end of a message, conversation turn, or sequence. Their exact forms and meanings depend on the model and its chat format.

An **end-of-sequence (EOS)** token signals that generation can stop. A message-ending token and a sequence-ending token are not necessarily the same. Use the model's tokenizer configuration, such as `tokenizer_config.json`, rather than memorizing token spellings across providers.

## Next-token prediction and decoding

Generation is **autoregressive**: each generated token becomes part of the context used to predict the next one.

1. Tokenize the input and represent its tokens and their positions.
2. Process the sequence to produce scores for possible next tokens in the vocabulary.
3. Use a decoding strategy to select the next token.
4. Append it and repeat until a stopping condition, such as EOS, is reached.

Two decoding strategies introduced in the course:

- **Greedy decoding:** always selects the highest-scoring next token. The best immediate choice does not necessarily produce the best complete sequence.
- **Beam search:** keeps several candidate sequences and compares their cumulative scores. This explores more possibilities than greedy decoding, without searching every possible sequence.

## Attention, context, and prompting

**Attention** lets the model weight relevant information in its context. For “The capital of France is …”, “capital” and “France” help determine the continuation.

**Context length** is the maximum number of tokens the model can handle within its context window. For generation, the prompt and generated continuation must fit within the supported limits.

The **prompt** is the input supplied to the model. Its wording and structure matter because generation depends on the tokens already in context. Clear instructions and relevant context help guide the output.

## Training

**Pretraining** learns patterns from large text datasets using targets derived from the text itself:

- Autoregressive models learn to predict the next token.
- Masked language models learn to recover hidden tokens.

This self-supervised training teaches language structure and patterns that can generalize to unseen inputs.

**Fine-tuning** further trains a pretrained model for particular behavior or tasks, such as following conversational instructions, using tools, classifying text, or generating code.

## Running an LLM

- **Locally:** run the model on your own machine if the hardware is sufficient.
- **Through a hosted API:** send requests to a model running remotely. The course primarily uses models through Hugging Face APIs, with local execution covered later.
