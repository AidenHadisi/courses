# Path Traversal

Path traversal (directory traversal) allows an attacker to read or write arbitrary files on the server running an application by manipulating file path references. It occurs when user input is passed directly to filesystem APIs without adequate sanitization or path canonicalization.

## Core Mechanism

- **Path traversal** abuses directory climbing sequences to escape the designated base directory and access the wider filesystem.
- **Impact**: Reading application code, database credentials, or sensitive OS files; arbitrary file writes can alter application logic or achieve full server compromise.
- **Traversal sequences**:
  - Unix / Linux: `../` (common target: `/etc/passwd`)
  - Windows: `../` and `..\` (common target: `\windows\win.ini`)

## Bypassing Common Defenses

Applications often attempt naive sanitization or validation on input filenames. Common bypass techniques:

| Obstacle / Defense | Bypass Technique | Example / Payload |
|---|---|---|
| Simple strip of `../` (non-recursive) | Nested traversal sequences that revert to `../` once stripped | `....//` or `....\/` |
| Strips relative traversal sequences | Absolute file paths | `/etc/passwd` |
| Web server/proxy strips `../` before routing | URL encoding or double URL encoding | `%2e%2e%2f` or `%252e%252e%252f` |
| Standard encoding blocked | Non-standard encodings (e.g., overlong UTF-8) | `..%c0%af` or `..%ef%bc%8f` |
| Requires path to start with base directory | Supply base folder prefix followed by traversal sequences | `/var/www/images/../../../etc/passwd` |
| Requires specific file extension (e.g., `.png`) | Null byte injection to truncate string before the extension | `../../../etc/passwd%00.png` |

## Prevention

The most effective prevention is avoiding user-supplied input in filesystem APIs entirely. When unavoidable, implement a two-layer defense:

1. **Input validation**: Validate input against a strict whitelist of permitted values, or restrict characters to an alphanumeric allowlist.
2. **Path canonicalization**: Append the input to the base directory, resolve the canonical path via filesystem APIs, and verify that the canonicalized path starts with the expected base directory.

```java
File file = new File(BASE_DIRECTORY, userInput);
if (file.getCanonicalPath().startsWith(BASE_DIRECTORY)) {
    // process file
}
```
