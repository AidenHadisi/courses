# Server-Side Vulnerabilities

Server-side vulnerabilities occur when an application mishandles user input before executing logic, accessing the filesystem, contacting backend services, or querying databases. Compromises range from sensitive data exposure to arbitrary operating system command execution.

## Path Traversal

**Path traversal** (directory traversal) allows an attacker to access arbitrary files on the server running the application by manipulating file path references.

- **Mechanism**: The application appends unsanitized input to a base directory path before reading or writing.
- **Traversal sequences**:
  - Linux/Unix: `../` steps up one directory level. Common target: `/etc/passwd`.
  - Windows: Both `..\` and `../` step up one directory level. Common target: `\windows\win.ini`.
- **Payload example**:
  ```http
  GET /loadImage?filename=../../../etc/passwd HTTP/1.1
  ```
  Resolves `/var/www/images/../../../etc/passwd` to `/etc/passwd`.
- **Impact**: Reading application code, database credentials, or sensitive OS files; arbitrary writes can alter code and yield full server compromise.

## Access Control

**Access control** enforces authorization constraints on which users can perform specific actions or access resources.

- **Authentication**: Verifies user identity ("who you are").
- **Session management**: Identifies subsequent HTTP requests from that identity.
- **Access control**: Determines permissions ("what you are allowed to do").

### Vertical Privilege Escalation
Gaining access to functionality reserved for higher-privileged users.
- **Unprotected functionality**: Sensitive endpoints (e.g., `/admin`) lack authorization checks and are discoverable via `robots.txt` or wordlist brute-forcing.
- **Security by obscurity**: Concealing sensitive endpoints (e.g., `/administrator-panel-yb556`) fails because endpoints leak in shared client-side code (e.g., role-conditional UI scripts sent to all users).
- **Parameter tampering**: Access decisions rely on user-controllable input (hidden fields, cookies, query parameters like `?admin=true` or `?role=1`).

### Horizontal Privilege Escalation
Accessing resources belonging to another user at the same privilege level.
- **Insecure Direct Object Reference (IDOR)**: Controllable parameters directly reference backend objects without ownership verification (e.g., changing `/myaccount?id=123` to `?id=124`).
- **Unpredictable IDs**: Using GUIDs prevents sequential enumeration, but IDs often leak in public contexts (user reviews, comments, public profiles).
- **Horizontal to vertical escalation**: Tampering with another user's account can target an administrator account (e.g., resetting password via administrative profile page).

## Authentication Vulnerabilities

**Authentication** verifies that a user is who they claim to be.

- **Brute-force attacks**: Automated trial-and-error using credential wordlists.
  - Predictable usernames: Corporate email patterns (`first.last@company.com`) or default admin names (`admin`, `administrator`).
  - Predictable passwords: Users adapt base words to fit complexity rules (`Password1!`) or make predictable changes during password rotation (`Password1?` $\to$ `Password2!`).
- **Username enumeration**: Detecting whether a username exists through behavioral differences (error message variations, response times, registration collision responses).
- **2FA bypass**: Flawed multi-stage logins where step 1 sets an authenticated session before step 2 completes, allowing direct navigation to internal pages.

## Server-Side Request Forgery (SSRF)

**SSRF** enables an attacker to coerce the server-side application into making HTTP requests to unintended internal or external resources.

- **Against the local server (`127.0.0.1` / `localhost`)**:
  - Bypasses front-end reverse proxy/firewall controls because requests originate from a trusted internal IP.
  - Accesses local administrative interfaces, disaster-recovery mechanisms, or unexposed loopback ports.
- **Against backend systems**:
  - Pivots through the server to reach non-routable private networks (e.g., `192.168.x.x`).
  - Explores internal backend APIs that omit authentication due to presumed network boundary security.
- **Example request**:
  ```http
  POST /product/stock HTTP/1.0
  Content-Type: application/x-www-form-urlencoded

  stockApi=http://192.168.0.68/admin
  ```

## File Upload Vulnerabilities

Occur when an application accepts user files without sufficient validation of name, type, contents, or size.

- **Web shell**: A malicious script enabling arbitrary command execution over HTTP:
  ```php
  <?php echo system($_GET['command']); ?>
  ```
- **Flawed MIME validation**:
  - The server only checks the client-supplied `Content-Type` header in the `multipart/form-data` body (e.g., accepting `image/jpeg`).
  - Attackers supply a script file with a spoofed MIME header to bypass validation if the server doesn't verify file contents.
- **Blacklist weaknesses**: Blacklists fail against alternate extensions (e.g., `.php5`, `.phtml`) or parsing discrepancies across web servers.

## OS Command Injection

**OS command injection** (shell injection) enables execution of arbitrary operating system commands on the server via vulnerable application input.

- **Command separators**: Characters such as `&`, `&&`, `|`, `||`, or `;` chain attacker commands to the application's command string.
  - Injected input `& echo test &` turns `script.pl <input> 29` into three sequential commands: `script.pl`, `echo test`, and `29`.
- **System reconnaissance commands**:

| Purpose | Linux | Windows |
|---|---|---|
| Current user | `whoami` | `whoami` |
| OS version | `uname -a` | `ver` |
| Network config | `ifconfig` | `ipconfig /all` |
| Active connections | `netstat -an` | `netstat -an` |
| Running processes | `ps -ef` | `tasklist` |

## SQL Injection (SQLi)

**SQL injection** allows an attacker to interfere with backend database queries to view, manipulate, or delete unauthorized data.

### Detection Methods
- Injecting `'` or `"` to trigger database syntax errors.
- Testing boolean conditions (`' OR 1=1--` vs `' OR 1=2--`) for differential responses.
- Injecting time-delay functions (e.g., `pg_sleep()`, `WAITFOR DELAY`).
- Out-of-band application security testing (OAST) to trigger DNS or HTTP interactions.

### Common Exploitations
- **Retrieving hidden data**: SQL comment sequences (`--`) truncate query logic, disabling filter constraints:
  ```sql
  -- Original query:
  SELECT * FROM products WHERE category = 'Gifts' AND released = 1
  -- Injected input: Gifts'--
  SELECT * FROM products WHERE category = 'Gifts'--' AND released = 1
  ```
- **Subverting authentication**:
  ```sql
  -- Injected username: administrator'--
  SELECT * FROM users WHERE username = 'administrator'--' AND password = '...'
  ```
  Matches the target user and comments out the password verification clause.

- **Warning on data loss**: Injecting `OR 1=1` into an input that flows into an `UPDATE` or `DELETE` statement will modify or delete every row in the table.
