# Introduction

The AWS Certified Generative AI Developer – Professional exam is a scenario exam about using foundation models on AWS, not about training them. This section is who it is for, what the course covers, and how to run the labs without a surprise bill.

## The exam

Professional level: long scenarios with competing requirements, and you pick the best implementation. It is not "which service does X."

It replaces the Machine Learning Specialty exam, which AWS phased out in early 2026. Same difficulty band. Closest prior cert is **Machine Learning Engineer – Associate**. **AI Practitioner** helps with the business framing. Data-engineering knowledge helps even though AWS lists it as out of scope.

Official target candidate:

- 2+ years with AWS, machine learning, and AI
- 1+ year implementing generative AI solutions
- Not a first certification. Assumes S3, IAM, storage, and security

Out of scope: building models from scratch, classical machine learning, and data engineering or feature engineering as their own topics. Data pipelines and data manipulation still show up, so the "no data engineering" line is loose.

The course is not organized by exam domain. Domains overlap, so it builds from fundamentals upward instead. Later sections on analytics, compute, containers, databases, developer tools, networking, and storage are in scope on the exam but are review; skip a lecture when the service is already familiar.

## What the course covers

**Generative AI and Bedrock.** Foundation models (GPT-class models, Amazon Nova, Amazon Titan, Claude), fine-tuning and the data format it needs, retrieval-augmented generation (RAG) via Bedrock knowledge bases and vector stores, guardrails, prompt management, Bedrock Flows, and light enterprise integration.

**Data for generative AI.** Getting data into a vector store: Bedrock Data Automation (structured output from unstructured input), SageMaker Data Wrangler, Transcribe, Comprehend, Glue for extract-transform-load, and CloudWatch while pipelines run. OpenSearch is the main vector store for knowledge bases on this exam, including GenAI-specific tuning. RDS and Aurora are alternatives. DynamoDB can feed OpenSearch. S3 basics are assumed; lifecycle management is not.

**Agentic AI.** Bedrock agents, multi-agent workflows, Strands Agents (a Python SDK), and AgentCore for deploying agents at scale with memory and tools. Human-in-the-loop when a step is too important to leave to the model. Amazon Q is the developer-productivity side of the same idea.

**Operational efficiency.** A large part of the exam. Context and token cost, picking a smaller model at runtime when it is enough, throughput, caching, resilient systems, foundation-model performance, and allocating only the resources you need. **Cross-region inference** spreads load and is required for some applications, not only for scale.

**SageMaker AI.** The alternative to Bedrock when you need more control, or a model that is not a Bedrock foundation model. Covers processing, training, and deployment, safe rollout and rollback, Ground Truth for labels, Model Monitor for drift, Clarify for why a model decided something, Model Registry, lineage, SageMaker Neo for edge, and SageMaker Pipelines.

**Applications around the model.** Lambda, API Gateway, AppConfig, Step Functions (including circuit breakers), EventBridge, CodeBuild, CodeDeploy, CodePipeline, AppSync, Outposts, Wavelength, and Amplify. An event-driven buffer between incoming data and the model is the resilient pattern.

**Governance and security.** Prompt management, agent tracing, evaluation, responsible AI, CloudWatch, CloudTrail, X-Ray, and Lake Formation for data access. Security is the usual set, applied to GenAI: IAM, KMS, Macie, Secrets Manager, Cognito, VPC, and PrivateLink.

## Running the labs

Code, data, slides, and a PDF study guide: [sundog-education.com course materials](https://www.sundog-education.com/ultimate-aws-certified-generative-ai-developer-professional-course-materials/).

Udemy's hosted AWS lab is only for Personal Plan or Udemy Business Pro. Otherwise use your own account. Following the cleanup steps should keep the labs to a few dollars.

**Signup.** A new AWS account may offer a simplified signup that signs in with credentials from another service and organizes the console by project. That console has a limited set of services and will not match these labs. If that screen appears, choose **Sign up (advanced)** so you get the full console.

**Billing alarm.** Create one before the hands-on work so a forgotten resource does not run all month.

1. In the console, search for Billing, then Budgets and planning → Budgets → Create budget.
2. Use a template. **Zero spend budget** only if you will watch the labs instead of running them. Otherwise **Monthly cost budget**.
3. Set a cap you will notice (the demo uses $20) and an email address.
4. Create budget. AWS emails you if the month crosses that amount.
